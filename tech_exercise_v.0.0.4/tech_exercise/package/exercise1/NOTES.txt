Starting code base flaws:
The GetAstronautDutiesByName action sends GetPersonByName instead of GetAstronautDutiesByName.
SQL concatenation with user input. This is venerable to sql injections. I chose to use EF core instead of dapper for ease of reading, better security, and consistency. (Could also use Dapper parameters)
In the GetAstronautDutiesByName query, a potentially null person value is used before a null is checked for. This could cause a null reference error. 
In AstronautDutyController CreateAstronautDuty not using try/catch.
In PersonAstronaut CurrentRank and CurrentDutyTitle are non-nullable strings and yet a person can have no astronaut details risking a null reference exception.
Career end date is set inconsistently depending on if the duty is being created vs updated. 
In the GetPeople query, the context is set to public read only exposing the DbContext unnecessarily.
Information leakage in exception messages. 
App setting "AllowedHosts": "*" should be more restricted for production.
